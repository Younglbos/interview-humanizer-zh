# 如何评测

所有案例均为虚构教学材料。评测事实和任务边界，不判断作者身份。

1. 在支持 Skills 的助手中加载根目录的 `SKILL.md`，让助手能读取 `references/`。
2. 从 `cases.json` 逐条只提供 `request` 和 `input`，每例使用独立会话；先不要给模型 `checks`。
3. 保存原始输出，按 `checks` 人工核对。可接受多种措辞，不能用与示例文字是否相同来判定。
4. 补充不同长度、不同体裁、存在口误和多方分歧的已获授权真实材料，核对关键事实和原话。不要把私有采访原文提交到公开仓库。

出现任何无依据的具体事实、伪造直接引语、归因变更、关键限定丢失或匿名泄露，都算该例失败。其余再评价信息取舍、连贯性、语域和人物声音。失败时记录输入、输出与具体问题，针对问题修订后复测相关案例。

## 当前验证范围

本次对技能结构、引用文件和上游正文完整性做本地检查；[手工演练](reviewed-examples.md) 展示四个场景的输出和核对。演练由编写技能的同一助手完成，未进行独立模型盲测，也未验证跨模型成功率；其余案例提供给使用者继续评测，不声称全部行为测试通过。

豆包对话评测时，先提供根目录 `DOUBAO_PROMPT.md` 的完整内容，再按以上方法逐条提供案例。当前未完成豆包客户端实测或平台 Skill 接入校验；对话指令文件不代表已安装平台技能。平台接入方式参考 [豆包官方 Skill 接入指南](https://open.doubao.com/document/doubao-developer-guide/skill-integration-guide)。
